About

One job, one machine.

Ignitify runs code you did not write, on hardware you do not want it to reach. Every job gets its own Firecracker MicroVM — booted for that work, destroyed when it ends.

The idea

Isolation you do not have to configure.

Running someone else's code is a containment problem before it is a scheduling problem. The usual answer is a container, which shares the host kernel with everything else on the box — so the isolation is only as good as the sandbox around it, and that sandbox is reused.

Ignitify does not reuse one. Each run gets its own kernel, its own root filesystem and its own network namespace, and the whole machine is thrown away at the end. There is nothing to escape into, because there is nothing left.

A machine per job

Not a process, not a container. A MicroVM with its own kernel, started for one run and gone afterwards.

Limits that refuse early

What a plan allows is checked when a run is admitted, with a reason — not discovered halfway through by something failing.

Bare metal underneath

Firecracker needs /dev/kvm. Nesting it inside another hypervisor costs the thing we are selling, so the fleet runs on real hardware.
