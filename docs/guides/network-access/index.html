Network access

A task has no network until you ask for it. Set execution.network in task.yaml to let it call out, or to serve requests.

1 · Allow outbound hosts

Set type: egress and list the hosts the task may reach; leave the list out to allow all hosts, or write [] to allow none.

2 · Check it offline

task:validate refuses a network block that does not fit together before you deploy.

3 · Reach an allowed host

A call to a host on the list works.

4 · See a blocked host

A call to any other host is cut off, and the task sees a reset connection.

Warning

Outbound network is on every plan. Inbound needs a plan that allows it: free may not; starter/team/pro/enterprise (on request) may.

5 · Serve requests

Use type: bidirectional with the port the task listens on and the paths you open, because a path you do not list is refused.

6 · Choose what a second run does

A bidirectional task runs one VM at a time, and --on-busy picks whether a second run waits (queue, the default) or fails at once (reject).

Note

--on-busy also applies to every other task when no host has room: queue waits for a limited time, and reject fails the run at once.
