Guides

Use an AI client

The Ignitify AI harness is an open-source (Apache-2.0) set of skills, prompts, templates and examples. It teaches your AI client how Ignitify works and how to use the ignitify CLI, so it can write a task, find why a run failed, or explain a failed build.

What it is

  • Your client, your model. Ignitify makes no model call for the harness. Your AI client (Claude Code, an IDE assistant, or any client that reads files and runs shell commands) reads it and uses its own model.
  • The CLI is the only tool. The client runs ignitify … commands with the key you give it. There is no extra server.
  • Your own work only. It covers your tasks, deployments, runs, recurring schedules, secrets, webhooks, limits and usage.

The repository holds skills in the open Agent Skills format, sample prompts (diagnose a run, write a task, review a task.yaml, explain a failed deploy, prepare a support report), task.yaml starters for Node, Python, Go and Rust, small working examples, a Claude Code plugin, and an AGENTS.md block for other clients. A skill for Terraform and OpenTofu (ignitify-terraform) helps the client write the configuration that sets up your tenant as code. See Manage a tenant with Terraform.

1 · Install the CLI

The client needs the CLI, version 3.3.0 or later. You sign in once yourself, to get the owner key that creates the client's key. See Install and sign in.

2 · Add the harness to Claude Code

Add the repository as a plugin source, then install the plugin.

The skills load when they apply. The plugin adds the commands /ignitify:diagnose-run, /ignitify:write-task, /ignitify:review-task-yaml, /ignitify:why-deploy-failed and /ignitify:prepare-support-report.

Or use the install script

The script downloads one tagged release, checks its SHA-256, and copies files. It needs no root and no npm, and --uninstall removes exactly what it installed. Read the script before you run it.

This puts the skills and commands in ~/.claude. To check the download, add --sha256 <hex> with the checksum from the release notes. Add --scope project to use ./.claude instead.

This puts the files in ./.ignitify-harness. Then add the block from AGENTS.md to your project.

Other clients, by hand

Copy the skills/ folder into the skills folder of your client. Copy the block in clients/generic/AGENTS.md into your project's instruction file. The README has the details.

Give the client a read-only key

Give your AI client its own key that can only read. Then a client that ignores its instructions still cannot deploy, run, delete or read secrets. You need CLI 3.2.0 or later, and an owner key (the key from ignitify login).

The last command writes the key to a new file (mode 0600). The key is shown once. Give the key to the AI client only through IGNITIFY_API_KEY in the environment of that client, for example in the shell or the settings you start the client from. Keep it out of your own shell profile, so your own commands still use your owner key. Then delete the file.

When the client runs ignitify whoami, the This Key block shows user ai-assistant and the six read permissions. A write is refused with permission-denied. To stop the client, run ignitify key:list --user ai-assistant, then ignitify key:revoke <key-id>. Users, groups and permissions has the details.

Use it safely

Your own key is full access

Without its own key, your AI client uses the key you signed in with. It can do what you can do: deploy, run (a run uses your plan and costs compute), cancel and delete. Give it a read-only key, as shown above.
  1. The skills tell the client to read freely, ask before every write, and never delete, use secret commands, or run login and logout. These are instructions, not a lock. A client can ignore them. The read-only key is the lock.
  2. In Claude Code, add the rules from clients/claude-code/settings.example.json to your .claude/settings.json. They allow read-only commands, ask before writes, and deny the destructive and secret commands.
  3. Give the client only its read-only key. Do not put your owner key in the environment of your AI client.
  4. If you add a write permission to the client's group, read every command your client proposes. Do not approve --yes on a delete you did not ask for.
  5. Your client sends what it reads (run logs, results, task.yaml) to its model vendor. Keep secrets out of logs and results.
  6. Run logs and results are written by your code. The skills tell the client to treat them as data, not as instructions.
