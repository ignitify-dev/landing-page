Install & sign in

Install the CLI, sign in once with your Google account, and check that it works. It takes three steps.

1 · Install the CLI

You need Node 22.13 or newer. The CLI is an npm package named ignitify.

Note

The line after the version tells you the CLI reached the platform. It can end with (minimum client …).

2 · Sign in

A new account starts on the free plan, with no key. The CLI gets its key when you run ignitify login and approve it in your browser.

The CLI also opens the page in your browser. Do these steps there:

  1. If the page asks, sign in with Google. The first sign-in creates your account on the free plan.
  2. Compare the code on the page with the code in your terminal. They must be the same.
  3. Choose Approve. Choose Deny if you did not run ignitify login yourself.

The terminal then prints the line that starts with ✓ Signed in.

No browser on this machine

Run ignitify login --no-browser. The CLI prints the page and does not open it. Open the page on any device that has a browser.

The code is short-lived

The code works for 10 minutes. If it expires, the CLI says so. Run ignitify login again.

Name the key

Each machine has one key. Its label is the host name of the machine. Use --name to choose another label, for example when two machines have the same host name.

A second login with the same label replaces the old key. The old key stops working. The free plan allows one key. If your account is at its key limit, the approve page asks you to pick the key to replace.

3 · Check it works

ignitify whoami shows your workspace, your plan and what you use. More lines follow the part shown here.

Your account page

Open account.ignitify.dev/web/profile and sign in with Google. The page shows:

PartWhat it shows
WorkspaceThe name, the id (tnt_…), the status and the plan of your workspace.
Plan limitsA table of what your plan allows: tasks, running VMs, pinned VMs, image storage and scratch storage per VM.
KeysEach key with its label, id, when it was last used, when it expires, when it was created and how it was issued. Choose Revoke to stop a key at once.
Use the CLIThe command ignitify login, where the CLI saves your key (~/.config/ignitify/credentials.json), a short list of useful commands and links to these docs.

The page never shows a key

The account page lists keys but never shows the secret. A key goes to your machine only through ignitify login. If you lose a key, revoke it on the page and run ignitify login again.

Choose Sign out on the page to end your browser session. This does not revoke any key.

Sign out of the CLI

ignitify logout revokes the key of this machine, then deletes the saved file.

If the platform cannot be reached, the CLI still deletes the file. It then warns you that the key may still work, and exits with code 1. Revoke the key on your account page.

Note

If the IGNITIFY_API_KEY environment variable is set, ignitify logout does not change it and does not revoke it. It prints a note.

Where the key is stored

The CLI saves the key in ~/.config/ignitify/credentials.json. If XDG_CONFIG_HOME is set, the file is $XDG_CONFIG_HOME/ignitify/credentials.json. Only you can read it (mode 0600). The CLI refuses a file that is a link, that belongs to another user, or that other users can read.

The key lasts 90 days without use. Each use renews it. It is tied to the server that issued it, so the CLI never sends it to another address.

Upgrade

CI keys are not available yet

You cannot get a key for CI or scripts today. A key comes only from ignitify login, which needs a person to approve it in a browser. A way to make a key for CI is planned, but not released.

The CLI reads the IGNITIFY_API_KEY environment variable first. If it is set and not empty, the CLI uses it instead of the saved key.
