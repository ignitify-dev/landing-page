Access control

Give people and programs their own keys, with only the permissions they need.

permission:list

List every permission a group can grant, and what each allows.

  • no API key
  • --json: full
FlagValueDefaultDescription
--json——Print the permissions as JSON.

Note

deployments.write plus runs.write can read secret values in practice, so treat them as secrets.read and more.

Note

tasks.write can delete deployments and runs (a task delete takes everything under it), and hooks.write can start runs and send run results to any URL, so grant each only where the writes it reaches are acceptable too.
Related
  • group:create
  • group:grant
  • group:get

user:create

Create a user that holds keys and is in groups.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<name>required——Lower case letters, digits and -, unique in your account.
--json——Print the user as JSON.

What happens

  1. Checks the name before it sends anything.
  2. Creates the user.
  3. Prints the user.

Note

A user has no password and cannot sign in, so add it to a group to give it permissions.

Note

It needs an owner key.

user:remove

Remove a user and revoke every key of the user.

  • needs API key
  • asks to confirm
  • deletes data
  • --json: full
FlagValueDefaultDescription
<name>required——The user name.
--yes, -y——Skip the question.

What happens

  1. Prints which user it will remove.
  2. Asks you to confirm, unless you pass --yes.
  3. Removes the user and revokes its keys at once.
  4. Prints how many keys it revoked.

Note

The name can be used again after the remove.

Note

It needs an owner key.

group:create

Create a group with a set of permissions.

  • --json: full
FlagValueDefaultDescription
<name>required——Lower case letters, digits and -, unique in your account.
--permissionsrequired<p1,p2,…>—The permissions the group grants, comma-separated. Required.

group:grant

Add one permission to a group.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<name>required——The group name.
<permission>required——One permission from permission:list.

What happens

  1. Checks the permission before it sends anything.
  2. Adds it to the group.
  3. Prints the group as it is now.

Note

The users of the group get the permission at their next request.

key:create

Create an API key for a user.

  • needs API key
  • --json: full
More examples (1)
FlagValueDefaultDescription
--userrequired<name>—The user the key belongs to. Required.
--labelrequired<text>—A name for the key, such as where it is used. Required.
--out<file>—Write the key to this new file at mode 0600 and print only its id. It fails when the file exists.
--json——Print the answer as JSON. Without --out it holds the raw key.

What happens

  1. Checks the user name and the label before it sends anything.
  2. With --out, creates the new file first, so a refused file costs no key.
  3. Creates the key.
  4. Prints the key once, or writes it to the file and prints only its id.

Note

The key is shown once, so hand it over by hand and keep no copy.

Note

Owner keys come from ignitify login; this command makes user keys only.
Related
  • key:list
  • key:revoke
  • user:create

key:revoke

Revoke an API key so that it stops working at once.

  • needs API key
  • asks to confirm
  • deletes data
  • --json: full
FlagValueDefaultDescription
<key-resource-id>required——The key id, from key:list.
--yes, -y——Skip the question.

What happens

  1. Prints which key it will revoke.
  2. Asks you to confirm, unless you pass --yes.
  3. Revokes the key.
  4. Prints the key id.

Note

It can revoke any key of your account, an owner key too.

Note

It needs an owner key.
