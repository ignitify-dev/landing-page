CLI reference

Runs

Read, stop and delete runs.

run:list

List your runs, with filters.

  • needs API key
  • --json: full
FlagValueDefaultDescription
--statusS—Only runs in this status, for example FAILED.
--deployment-idD—Only runs of this deployment.
--task-nameN—Only runs of this task.
--presetP—Only runs on this instance class.
--correlation-idC—Only runs with this correlation id.
--vm-idV—Only runs that used this VM.
--limitN—Rows on the page. The server sets the default and the largest value.
--after<iso>—Only rows after this ISO 8601 time.
--after-id<id>—Page cursor. Pass the id of the last row of the page before.

Note

Runs are listed newest first, so --limit 1 returns your latest run; page to older runs with --after-id.

Note

A filter you misspell is an error, so a typo cannot give you an unfiltered list.

run:get

Show one run: status, timing and the result of the task.

  • needs API key
  • --json: full
More examples (1)
FlagValueDefaultDescription
<run-id>required——The run id, from task:run or run:list.
--full——Print the whole run as JSON, with every field the API returns.

Note

The result is cut after 40 lines, and --full shows all of it.

Note

A failed run shows the error as its result.

run:logs

Print the console output of a run, exactly as the task wrote it.

  • needs API key
  • --json: none
FlagValueDefaultDescription
<run-id>required——The run id.

Note

It prints what exists now and does not stream, so run it again to see more.

Note

A long log is cut at a size cap, and a note on stderr says so.

run:cancel

Stop a live run, gracefully by default.

  • needs API key
  • asks to confirm
  • --json: full
More examples (2)
More examples (1)
FlagValueDefaultDescription
<run-id>required——The run id.
--yes, -y——Skip the question.
--force——Kill the run now. It is also needed when the run is on a pinned VM.
--grace<ms>—Ask for a longer wind-down, in whole milliseconds. The server limits it.

What happens

  1. Reads the run, because a finished run needs no cancel.
  2. Asks you to confirm, unless you pass --yes.
  3. Asks the run to stop, or kills it at once with --force.
  4. Prints what the server did.

Note

A graceful stop leaves the run RUNNING until the task finishes or the grace time ends.

Note

--force does not skip the question; only --yes does.

run:delete

Delete the record of a run, without stopping its VM.

  • needs API key
  • asks to confirm
  • deletes data
  • --json: full
FlagValueDefaultDescription
<run-id>required——The run id.
--yes, -y——Skip the question.

What happens

  1. Prints which run it will delete.
  2. Asks you to confirm, unless you pass --yes.
  3. Soft-deletes the run record.
  4. Prints the run id.

Note

A live run is marked CANCELLED and hidden, but its VM keeps going, so use run:cancel first to stop it.
