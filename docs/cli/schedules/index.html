Schedules

See and cancel runs that wait for a time.

schedule:create

Run a task again and again on a cron schedule.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<task>required——The task (slug or id). Each slot runs its newest READY deployment.
--cronrequired<expression>—Five fields: minute, hour, day of month, month, day of week. Quote it.
--tz<zone>UTCThe IANA time zone the expression reads in, for example Europe/Berlin.
--payload<json>{}JSON input for every run.
--preset<preset>the deployment's run.preset when it firesInstance class for every run.
--timeout-sec<n>the deployment's run.timeout_sec when it firesTime limit in seconds for every run.
--deadline-sec<n>—A hard wall-clock limit in seconds for every run, at least the time limit.
--overlapskip|allowskipWhen the last run is still live: skip leaves this slot out, allow starts it too.

Note

Your plan limits how many schedules you keep, and paused ones count.

Note

After many failed slots in a row the platform pauses the schedule and sends a notification, and a slot with no READY deployment counts, so deploy the task first.

schedule:list

List your schedules: one-time and recurring.

  • needs API key
  • --json: full
More examples (1)

Note

A schedule is not a run, and no run exists until it fires.

Note

A one-time schedule shows only until it fires, and a recurring one until you cancel it.

schedule:show

Show one recurring schedule: state, run settings and next fire times.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<sch-id>required——The schedule id, from schedule:create or schedule:list.

Note

auto_paused means the platform paused it, and pause_reason says why.

Note

The payload is never shown, and only recurring schedules show here, so a one-time run waits under schedule:list.

schedule:update

Change a recurring schedule in place, keeping its id, runs and miss count.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<sch-id>required——The schedule id, from schedule:create or schedule:list.
--cron<expression>unchangedA new expression: minute, hour, day of month, month, day of week. Quote it.
--tz<zone>unchangedA new IANA time zone for the expression, for example Europe/Berlin.
--payload<json>unchangedA new JSON input for every run. It replaces the whole payload, and the old one cannot be read back.
--preset<preset>unchangedA new instance class for every run.
--timeout-sec<n>unchangedA new time limit in seconds for every run.
--deadline-sec<n>unchangedA new hard wall-clock limit in seconds for every run, at least the time limit.
--overlapskip|allowunchangedWhen the last run is still live: skip leaves the slot out, allow starts it too.

Note

Only the fields you give change, and a new expression or zone counts the next slot from now.

Note

The status does not change, so a paused schedule stays paused until schedule:resume.

schedule:pause

Pause a recurring schedule: it fires nothing until you resume it.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<sch-id>required——The schedule id.

Note

A run that already started goes on, and a paused schedule still counts against your plan limit.

Note

Pausing a schedule the platform paused closes its notice and clears pause_reason.

  • schedule:resume

schedule:resume

Resume a paused recurring schedule.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<sch-id>required——The schedule id.

Note

The next slot counts from now, so slots missed while it was paused never fire.

Note

It also resumes a schedule the platform paused, so fix the cause in pause_reason first, and on a plan without recurring schedules change plan first (a resume there is refused with capability-denied); after a platform incident, the Run later guide gives a loop that resumes only the schedules paused since the incident started.

schedule:preview

Print the next fire times of a cron expression without creating anything.

  • needs API key
  • --json: full
FlagValueDefaultDescription
<cron>required——The expression, in quotes: minute, hour, day of month, month, day of week.
--tz<zone>UTCThe IANA time zone the expression reads in.

Note

The times print in UTC.

Note

It needs the same permission as schedule:create.
Related
  • schedule:create

schedule:cancel

Cancel a schedule of either kind so that it never fires again.

  • needs API key
  • asks to confirm
  • deletes data
  • --json: full
FlagValueDefaultDescription
<sch-id>required——The schedule id, from task:run --at, schedule:create or schedule:list.
--yes, -y——Skip the question.

What happens

  1. Prints which schedule it will cancel.
  2. Asks you to confirm, unless you pass --yes.
  3. Cancels the schedule.
  4. Prints the schedule id.

Note

A recurring schedule is deleted, and the runs it started stay.

Note

If the schedule is missing, already fired or firing now, the command says so and exits 1.
