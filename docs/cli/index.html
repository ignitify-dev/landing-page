Sign in with an API key

Every command that talks to the platform needs your tenant API key. Run ignitify login once on each machine, or set the IGNITIFY_API_KEY environment variable, which wins.

Never put the key in task.yaml. The CLI sends it as a bearer token with each request.

Each command page shows a badge. It says if the command needs the key or can run offline.

Environment variables

The --dir flag wins over the variable. The variable wins over the default.

NameMeaning
IGNITIFY_API_KEYYour tenant API key.
IGNITIFY_TASKS_DIRFolder that holds your task folders. Default: tasks, from where you run the command.

Global flags

These flags work on every command.

NameMeaning
--jsonPrint one JSON document on stdout. Messages go to stderr.
--helpPrint the usage of the command and stop.

Short flags

There are three short flags. No other short flag exists.

NameMeaning
-hThe same as --help. Works anywhere.
-yThe same as --yes. Works anywhere, on commands that have --yes.
-vThe same as --version. Works only as the first word.

A flag or an argument that a command does not take is an error, not ignored.

Output

A command prints its result on stdout. Progress lines, notes, warnings and questions go to stderr.

Colour is used only when the output is a terminal. A progress line is drawn only on a terminal, and a pipe gets one line per phase.

The --json rule

With --json, a command that succeeds prints exactly one JSON document on stdout, and nothing else. The keys are snake_case.

A command with nothing to report prints a short document about its outcome, for example the schedule id and cancelled.

A command that fails prints nothing on stdout. Read the error on stderr.

One exception: task:run --wait prints the finished run even when it did not complete, because that run is the result.

Errors and the trace id

An error prints on stderr as Error: and a message.

After an error from the server, the CLI also prints server trace id: and an id. Give this id to support.

An answer that the CLI cannot explain better is shown as API, the status and the server's body.

Exit codes

A command page lists an exit code only when it differs from this table.

NameMeaning
0The command did what you asked.
1It did not: an error, a refusal, bad input, a declined question, or a run that did not complete under --wait.
130You pressed Ctrl+C while the CLI waited. Nothing was cancelled on the server.

Confirmations

Delete and cancel commands ask Proceed? [y/N] before they act. Only --yes skips the question.

--force is different. It unlocks a refusal, for example a pinned VM, and the command still asks.

With no terminal and no --yes, the command refuses and exits 1.

Pagination

A list command returns one page. --limit sets the page size, and the server sets the default and the largest value.

For the next page, pass the id of the last row as --after-id. The --after flag is a time filter, not a cursor.

vm:list pages by boot time. Pass booted_at and vm_id of the last row as --after and --after-vm-id.

Waits

task:deploy waits up to 15 min for the build. task:run --wait waits up to 30 min for the run.

The CLI asks again with a growing pause, from 0.5 to 1 s for a deploy and from 0.5 to 3 s for a run.

When the time is up, or when you press Ctrl+C, the CLI stops waiting. It cancels nothing on the server.

A failed check is tried again. The CLI gives up after 3 failures in a row that last at least 60 s.

Timeouts and limits

A write that times out may still complete on the server. The error says so; check before you repeat it.

NameMeaning
Request120 s for each call to the server.
Upload300 s for the upload of a deploy. The task folder may hold up to 64 MiB.
Package review60 s for task:validate --review-packages.
Version check3 s for ignitify --version.
Payload and resultA run takes at most 10 KiB of input and gives back at most 10 KiB.

run:get shows the first 40 lines of a result, and a failed build shows the last 30 lines of its log.

Version check

Every server answer names the oldest client that the API supports. An older client prints one warning on stderr and keeps working.

ignitify --version prints the client version and the API version.
