Tasks

Create, check, deploy and run a task from your own folder.

task:create

Register a task name and write the starter files for it.

  • needs API key · offline with --local
  • --json: full
More examples (1)
More examples (1)
FlagValueDefaultDescription
<task-id>required——The task name. It is also the folder name and the slug in task.yaml.
--dir<base-dir>$IGNITIFY_TASKS_DIR, else tasksFolder that holds your task folders.
--langnode|python|go|rustnodeLanguage of the starter files.
--local——Write the files only. Calls no server and needs no key.
--no-init——Write the short starter that has only run(), without init code.
--no-scaffold——Register the task name but write no files.

What happens

  1. Checks the task name and the language.
  2. Registers the name with the server.
  3. Saves the task ids in .ignitify/state.json.
  4. Writes task.yaml, the entry file, the lockfile and README.md.

Note

A task name stays reserved for your account once it is registered, so check the spelling.

Note

With --local nothing is registered, so task:deploy fails until you run task:create without it.

task:deploy

Upload your task source and wait until the platform has built it.

  • needs API key · offline with --check
  • waits
  • --json: full
More examples (2)
More examples (1)
FlagValueDefaultDescription
<task-id>required——The task folder name.
--dir<base-dir>$IGNITIFY_TASKS_DIR, else tasksFolder that holds your task folders.
--check——Run every local check, then stop. Nothing is uploaded.

What happens

  1. Checks the folder on your machine.
  2. Uploads the task source.
  3. Waits for the platform to build the image, up to 15 min.
  4. Prints the deployment.

Note

Ctrl+C stops the wait, not the build.

Note

Unchanged code is reused, so no new build runs and the output shows reused true.

task:run

Start one run of a task from its latest deployment.

  • needs API key
  • waits
  • --json: full
More examples (2)
More examples (2)
FlagValueDefaultDescription
<task-id>required——The task folder name.
--deployment<id>the task's latest deployRun this deployment instead of the task's latest deploy.
--payload<json>run.payload from task.yamlJSON input for this run only. The limit is 10 KiB.
--timeout-sec<n>run.timeout_sec from task.yamlTime limit in seconds for this run only.
--on-busyqueue|rejectqueueWhen a host or a bidirectional task's one VM is busy, queue waits for room and reject fails at once. A full plan limit refuses either way.
--at<iso>—Schedule the run for this ISO 8601 time instead of starting it now.
--wait——Follow the run to its end, then print the run and its result.
--dir<base-dir>$IGNITIFY_TASKS_DIR, else tasksFolder that holds your task folders.

What happens

  1. Checks the flags and the payload size on your machine.
  2. Picks the latest deployment, or the one you name.
  3. Submits the run.
  4. With --wait, follows the run to its end.

Note

With --wait the exit code is 0 only when the run is COMPLETED.

Note

Ctrl+C stops the wait, not the run.

task:delete

Delete a task with all its deployments and runs.

  • needs API key
  • asks to confirm
  • deletes data
  • --json: full
FlagValueDefaultDescription
<task-id>required——The task folder name, or the task id.
--dir<base-dir>$IGNITIFY_TASKS_DIR, else tasksFolder that holds your task folders. The command looks there for linked folders.
--yes, -y——Skip the question. The list of what will be deleted still prints.
--json——Print the plan and the result as one JSON document.

What happens

  1. Counts what the task owns, and lists the runs that are still live.
  2. Asks you to confirm, unless you pass --yes.
  3. Deletes the task, its deployments and its runs on the server.
  4. Removes the .ignitify/ link in each local folder that points to the task.

Note

Live runs are cancelled and their VMs are destroyed.

Note

Your task files are kept, because the command never deletes a folder.
