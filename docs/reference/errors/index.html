Errors

Every failure prints an Error: line on stderr and exits with code 1 (130 if you press Ctrl+C during a wait). Find your line below. Each entry gives what it means and one command to fix it.

Troubleshoot covers exit codes and the trace id.

Three gates refuse a request

A refusal comes from one of three gates, and each has a different fix. A plan limit asks for a wait or a bigger plan. A capacity refusal asks for a short wait. A capability refusal asks you to change what you declare, or your plan.

Plan limits

A monthly limit is reached

The allowance of your plan for the month is used up (the Free plan has one for compute), and it resets at the time in the message. Fix: ignitify usage shows what you used.

You run too fast

Your plan allows a set number of runs in the window, and you used them: limit is that number and observed is how many runs you had already started in the window. Fix: ignitify whoami shows the limit; run again after the window.

You send requests too fast

Your plan allows a set number of API requests each second, and a script sent more. This is not the run limit above. Fix: slow the script, then send the request again.

A bidirectional task already has a VM

A task that takes inbound traffic runs one VM at a time. Fix: ignitify task:run listen --on-busy queue waits for the VM.

Capacity

A capacity refusal means no host can fit your VM right now. It is not about your plan, and it never names a tier. Wait a short time and run again.

Note

No live capacity refusal has been recorded yet, so no example line is shown. Its JSON carries "boundBy":"host-capacity" in place of "tier-entitlement".

Capability

Your plan does not include it

Your plan does not allow this kind of work. Fix: ignitify whoami lists what your plan allows in its may_… lines.

A declaration is refused

The platform refuses a value it cannot honour, and the line names the field. Fix: correct the field, then run ignitify task:validate fetch again. Refused values lists every case.

Before the request is sent

No API key

The CLI has no key to sign in with. Fix: export API_KEY=<your-key>. A key that is wrong or revoked answers Error: API 401.

Unknown flag

The flag is not one of that command's flags. Fix: ignitify help task:run lists the flags of one command.

The payload is too large

The payload is over the limit of 10 KiB. Keep large data in your own storage and pass a link in --payload.

Deploys and builds

No deployment found

The task has no deployment to run. Fix: ignitify task:deploy fetch.

The latest deploy is still building

A run needs a finished build. Fix: ignitify deployment:get 019fdec9-0c3e-7b52-a417-6e2d9f8b1c05 until its status is READY.

The build failed

The build stopped at the named stage, and the log tail shows why. Fix: ignitify deployment:get 019fdeca-6b14-7a90-8e23-c1d4f0a7b958 prints the failure and the last 30 lines of the build log.

The latest deploy failed

The newest build failed, so there is nothing new to run. Fix: change the task, then ignitify task:deploy broken.

Scripts and CI

A script cannot answer the question

A delete asks you to confirm, and a script has no keyboard. Fix: add -y to every delete in a script.

Read the reason, not the text

The words after Error: are for people and can change. For a refused request, read the reason and boundBy fields in the JSON after API <status>:.
