Build flows

Build flows

Ignitify runs one step in one VM. You build a flow from steps: state that goes from one run to the next, a way to start the next step, and the guides below. Each table here helps you choose, and links to the page that shows how.

What the platform does not do

A run cannot pause and resume. There is no built-in join of child runs, no retry policy for one step, and no flow view. Your own workflow tool, cron job or queue keeps the state of the flow and starts each step.

Pass state between runs

A run does not see the run before it. Pick one way to carry state from one run to the next. Pass state between runs shows each way with its limits.

Chain runs

A run ends with a result. The task can return which step comes next. The caller, or your own workflow tool, cron job or queue, starts that step.

WayWhere it livesUse it whenRead
The next step in the resultThe result of the run: which task, and which payload.The next step depends on what the task found. This is also how you branch and loop.The next step in the result
Your own orchestratorYour own workflow tool, cron job or queue. It keeps the state of the flow.The flow is larger than a few steps. Ignitify is the secure compute step that your tool calls.Your own orchestrator
Run B when A endsTask A's end-of-run callback calls task B's webhook. B gets A's run id and status, not its result.B needs to know only that A ended.Run B when A ends

Your orchestrator or the caller makes each shape from single runs. A run never starts other runs. Flow shapes shows each one.

Fan-inYour orchestrator waits for all parts, then combines the results.The next step needs every part.Fan-in
Branch and loopThe task returns the next step or "again". The caller starts it and counts.The next step depends on a result.Branch and loop

Safety and retries

The platform retries its own infrastructure failures. A task error is not retried: the caller or your orchestrator retries it.

WayWhere it livesUse it whenRead
No duplicate runsAn idempotency key on the request that starts the run.A script retries task:run after a network error.Retry a run safely
Platform retriesThe platform. Your plan sets the number of tries.You want to know what is retried for you, and what is not.Reliability
CancelOne command for one run. Your orchestrator cancels the runs it started.A run must stop, or the flow is no longer needed.Stop and clean up

See the flow

The platform shows each run. It does not show a flow. Put a flow id in the payload of every run and in its result, then read it back from the results.

WayWhere it livesUse it whenRead
Per-run viewThe CLI and the tenant app: status, result, logs, timeline, failures.You look at one step of a flow.Run commands
AlertsNotifications, for example a refused webhook or a reached limit. notification:list shows them.You want to be told when something stops a run.notification:list, Trigger from a webhook
UsageUsage and limits per tenant. There is no usage view per flow.You want to know what all your flows cost together.See what you used this month
