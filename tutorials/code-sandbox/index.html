Code sandbox for AI agents

Let an AI agent run the Python it writes, safely. Each snippet gets a fresh MicroVM with no network, a hard time limit and capped memory, and the agent gets back the output or the traceback.

What this tutorial proves

  • Code you did not write, including code an AI wrote, runs in its own MicroVM. One run, one VM, never shared.
  • With network: none the code cannot reach the internet, your other runs or your machine.
  • A hostile snippet (an endless loop, a memory bomb, a fork bomb) ends with a clear result, not a hung or crashed task.
  • An agent can use the platform as a tool: Claude writes the code, the task runs it, Claude reads the result.

What you build

  1. A Python task that takes a program in its payload, runs it, and returns stdout, stderr and the exit code.
  2. A short agent script on your machine. Claude gets one tool, run_python, and each call starts a run of the task.

The task's nature

SettingValueWhy

presetstd.small256 MiB. The snippet gets 128 MiB, the rest is the runtime and the VM.

Before you start

  • A plan with the std.small preset. This tutorial uses Starter.
  • The CLI, installed and signed in. See Install.
  • For the agent: Python 3.10 or later, the anthropic package, and an Anthropic API key.

Create the task

The code

The VM is the security boundary. Inside it, sandbox.py runs the program as a child process, so the task can still answer when the program hangs, crashes or floods its output. The child gets resource limits and an empty environment, and a timeout kills it with everything it started.

Create .ignitifyignore with one line, agent.py, so the agent script stays on your machine.

Validate and deploy

Run a snippet

The default payload prints the machine and the Python version. Pass your own program with --payload.

A program that fails is still a completed run. The result has ok: false and the traceback in stderr, which is what an agent needs to fix its code. Only a bad payload fails the run, for example code over 8 KiB.

Try to break it

We ran these snippets through sandbox.py. Each one ends with a clear result, and the task keeps working:

Two layers

These results come from the limits in sandbox.py, measured on a Linux machine. On the platform the MicroVM adds the outer layer: a fresh VM per run, no network, and nothing left behind when the run ends.

Give it to an agent

agent.py runs on your machine. It gives Claude one tool, run_python. The SDK's tool runner handles the loop: Claude writes a program, the tool runs it as a task run, and Claude reads the JSON result before it answers.

The script uses claude-opus-5-5, and turns on fallbacks: "default": if Claude declines a request on safety grounds, the API re-runs it on Anthropic's recommended fallback model.

Each tool call is a run

Every run_python call starts a new run in a new VM, so one snippet cannot see files or state from another. List them with ignitify run:list --task-name code-sandbox.
