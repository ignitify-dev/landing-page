The brain emits two kinds of record: a log and a metric.
A log goes to two sinks: the console and the timeline.
A metric goes to prom only.
The console sink writes one JSON line for each log record.
The line goes to journald. Alloy ships the journal to Loki.
Loki keeps a line for 180 days.
The timeline sink is the door to the durable trail. Only a named record can go in.
A plain log line stays on the console. An API access record stays there too.
The sink writes a file for each tenant. Every 5 seconds a shipper copies the files into a table.
The run timeline reads that table. A tenant sees only the events that are marked visible.
The output of a task goes to the serial console of its VM. That is a file on the fleet host.
This file is not shipped to Loki. It stays on the host after the teardown.
The tenant asks for it with run:logs. The brain asks the host agent for a slice of the file.
The bytes go back to the tenant. The brain does not store them.
Each brain shows its metrics at /metrics. Prometheus scrapes the two brains every 15 seconds.
The name of a counter ends in _total. An id, such as run_id, does not become a label.
The two brains report the same gauge. So a dashboard reads it with max, not sum.
A counter is different. A dashboard reads it with sum and increase.
Grafana reads three sources: Prometheus, Loki and Postgres. Its dashboards are files.
An alert rule is a query. Grafana checks A brain is down every 30 seconds.
One policy sends the alert to the contact point ignitify-operators: a Telegram group.
When the alert ends, a recovery message comes too.
Logs to Loki. Run events to the trail.
Metrics to Prometheus. Alerts to the operators.
