A task asks for inbound traffic in task.yaml. A route needs the type bidirectional and an inbound_port.
The platform makes the public name from the deployment id and the tenant id.
One wildcard certificate covers the names of all tasks.
The run starts on a new VM. Its paths are closed. A request to the name gets 404.
The task starts its server, then calls ctx.ready().
The brain makes the routes. On the host, the daemon writes them. Each proxy loads them with no restart.
Now the paths are open. With no ready signal in 30 seconds, the run fails.
The task reads its public address from ctx.callback.url. The stream integration makes the viewer link from it.
Hop 1. HTTPS to the public ingress. Public TLS ends there. No fleet host holds the public key.
Hop 2. Mutual TLS to the fleet host that serves the VM. The public ingress does not dial a guest.
Hop 3. The host ingress finds the guest from the Host header. It sends the request to the inbound_port.
A name with no route gets 404. A path that the task did not declare gets 404 too.
Each route has limits. The defaults: 100 requests each second, and 64 in flight for each vCPU.
On the host, only the host ingress can open a connection to a guest.
The run is over. This task does not keep its process for the next run, so its paths close.
Then the VM is torn down.
The brain sends the routes again. This VM is not in them. The name gets 404.
One name. Two proxies.
Open after ready. Gone after teardown.
