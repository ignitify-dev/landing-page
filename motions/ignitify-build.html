The CLI uploads the task source to a brain.
Same content, and that deployment is READY? The brain uses it again. No new build.
New content: the brain writes the deployment row and the build job in one transaction.
The brain packs the source into an image and puts it in the artefact store.
Then it starts a build MicroVM on a fleet host. The brain never builds.
By default, a build VM has 2 vCPUs, 2048 MiB of memory and 15 minutes.
New system packages? A packages build runs first. The code build follows it.
The tenant's build steps run here, with the isolation of a task.
Packages come through a package cache on the host. The internet is an allow list.
The build installs the dependencies from the lockfile. It bundles a Node task.
Then a test: the build starts the task one time.
The build VM is done. The host daemon hashes the image and signs the digest.
The brain checks the signature, then copies the image into the store. The brain is its one writer.
The deployment is READY. The store keeps the image by its content hash.
A build that fails makes the deployment FAILED. A build that loses its VM is tried again.
At READY, the brain tells each active host to fetch the image. This is best effort.
A host without the image fetches it when a run needs it. It keeps only bytes with the right hash.
The daemon hashes its own copy. The run VM mounts the drives read-only. Packages are optional.
Secrets go only to a VM that booted from the images of its run.
