A run needs a VM. The host daemon gets the order.
Each VM gets its own network slot and user id.
Wall 1: the jail. A private directory that only this VM's user can open. Then a memory limit.
Wall 2: Firecracker runs inside the jail as the VM's own user, with no capabilities.
Wall 3: the guest has its own kernel. The supervisor starts as its first process.
The supervisor gets its work on a private channel. The network is not used.
Tenant code runs as a low-privilege user. It cannot touch the control channel.
All its traffic goes through one fence on the host.
No rule trusts the guest. With a list, its web traffic reaches only those hosts.
The result goes back. A reusable VM stays warm for the next run of the same deployment.
No more work: the VM is killed, and the jail and its scratch disk are erased.
The slot, the user id and the memory go back. The next VM starts clean.
Three walls. Two channels.
Then it is gone.
